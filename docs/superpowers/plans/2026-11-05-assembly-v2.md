> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan unit-by-unit. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish `assembly-v2` as the sole forward trunk: a region-only serve shape built on the clean-room base `feat/synthetic-head-residency` (rebased onto stock v0.45.0), where every assembly-side mitigation must earn its place against the live API surface or is recorded as dead and dropped.

**Architecture:** v2 seeds at feat tip `0a15ac87f` — the reviewed region implementation (design rounds 1–4, storm fixes A/B/C, census hardening, Pi P2, Rust R2, profile self-description) with no FPE/R11/withdraw/splice strata. First act: sever the region renderer from the head-era `materializeM0` (rotation currently renders region bytes *through* the head renderer), then delete the m[0]/m[1] world — which converts every later "does this mitigation still have an API?" question into a build error. Second act: restore delta economics (volatile segment behind the frozen region, all DELTA triggers demoted). Then re-assemble the assembly-side fringe unit by unit, census-gated.

**Tech Stack:** TypeScript (Bun, `bun test`), `packages/plugin/`, `packages/pi-plugin/`, `crates/mc-module` (out-of-contract, parity only), SQLite host store, biome `@biomejs/biome@2.5.1`, mc-gate.

**Spec:** `docs/designs/frozen-system-region-residency.md` (§3 contract, §7 pass mechanics, §9 ports, §11 deletions, §21 flag deletion, §25 production-composition law) + `docs/superpowers/plans/2026-11-05-region-only-migration.md` (its Review Focus laws and red-first tests transfer verbatim into Unit 2).

## Governance (owner rulings 2026-11-05)

- **assembly = v1 maintenance trunk.** Frozen at ctxv18 lineage; block-field-fixes only; the region-only migration plan is retired as a v1 artifact (kept for law provenance).
- **assembly-v2 = the product trunk** and the seed of the from-scratch product (note #93); new-surface investment (invizipburu) lands here first.
- **Bust authority is binary** (owner law): the window manager (scheduler folds) and the harness (H changes, e.g. AGENTS.md via `system_hash`) are the only deciders. All other components — memories, notes, compartments, profile, docs — only *schedule* changes onto the volatile segment.

- **v2 placement line** starts after Unit 8 parity gates; numbering `0.45.0-mcv2.<n>`; rollback pair = latest ctxv.

## Review Focus

1. **Sever is byte-exact**: the extracted region renderer produces bytes identical to feat-tip production region output for real captured windows + fixture stores (golden captured *before* refactor through the production path).
2. **Deletion is total**: every §11 symbol has zero live references in a fresh census, and no test pins a deleted API (a law file guarding dead API is itself deleted — its protection must have a live-API successor or a recorded ruling).
3. **Boot law adjudication is a ruling, not a port**: `restore-only-boot-pass.ts` (assembly-only) vs the region `materialized_at` witness gets a written disposition with a red-first law reproducing the defect-4 receipt shape (cold boot → replay, zero fold).
4. **Quiescent writes cost zero**: memory/note write → region bytes unchanged, zero rotations, delta visible via volatile segment; growth backstop *requests* a fold, never re-renders the region.
5. **Re-assembly is census-gated**: no fringe file re-enters v2 without a named live caller in the current v2 tree; the census table is a committed artifact, and "not measured" is an admissible disposition only with a reopening trigger.
